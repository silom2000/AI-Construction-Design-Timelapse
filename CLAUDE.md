## Главный профиль проекта: Electron / React / Node

- Проект в первую очередь является Electron-приложением с React/TypeScript UI и Node.js backend handlers.
- Для любых изменений в `.tsx` обязательно запускай `npm run build`.
- Если добавляется новый мост `ipcRenderer.invoke`, обязательно обновляй `IElectronAPI` в `src/electron.d.ts`.
- Все объекты, props, API inputs/outputs должны быть типизированы.
- Никаких `any` для критических структур данных. Пиши интерфейсы рядом с использованием или в `.d.ts`.
- Оставляй React state точечным. Если удаляешь фичу или UI элемент, удаляй связанные `useState` и `useEffect`.
- Избегай глубоко вложенных тернарных операторов в render. Если UI-логика разрастается, выноси её в локальную render-функцию компонента.
- При изменении сложного JSX не используй Regex через Bash для больших HTML/JSX-блоков. Это ломает скобки и парсинг.

## Timelapse / G-Labs / FFmpeg

- Timelapse pipeline должен сохранять последовательность кадров: Image N является референсом для Image N+1.
- Для видео-переходов соблюдай правило: Video 1 = Image 1 -> Image 2, Video 2 = Image 2 -> Image 3 и так далее.
- Для image prompts явно фиксируй формат TikTok `9:16`, один полный кадр, без collage/split screen/storyboard/multi-panel.
- Камера Timelapse должна быть стабильной между этапами: тот же фон, перспектива, lens angle, масштаб и композиция.
- Если меняется количество этапов, обновляй backend, UI, сборку, сообщения ошибок и prompt schema одновременно.
- Для Veo/G-Labs video prompts явно прописывай звуковое сопровождение. Если музыка не нужна, запрет должен быть в самом prompt.
- Финальная сборка через FFmpeg должна проверяться на реальных путях файлов и не должна молча пропускать отсутствующие сегменты.

## Общие инженерные принципы

- **Mandatory Brainstorming:** перед кодом уточняй конечную цель, предположения и trade-offs, если задача неоднозначная.
- Если есть несколько равноценных вариантов решения с разными последствиями, предложи их пользователю.
- Если задача простая и минимальное решение очевидно, действуй без лишней задержки.
- **Simplicity First:** YAGNI и DRY. Читаемость важнее «умного» кода.
- **Surgical Changes:** меняй только то, что необходимо для задачи.
- Не улучшай соседний код, форматирование или комментарии без необходимости.
- Подстраивайся под существующий стиль кода.
- Убирай за собой импорты, функции и state, которые стали не нужны из-за твоих изменений.
- Проверяй работоспособность до сообщения об успехе.
- Сначала проверяй бизнес-требование, затем качество кода.
- Критические баги блокируют дальнейшую разработку до исправления.

## TDD и проверки

- TDD обязателен для новой бизнес-логики, алгоритмов и устойчивых багфиксов, где можно написать быстрый тест.
- Для UI/prompt/интеграционных правок допускается проверка через `npm run build`, syntax checks и ручную валидацию логики.
- Для Python-кода используй `pytest` + AAA, тестируй бизнес-логику и мокай внешние сервисы.
- Перед отчётом о завершении запускай релевантные проверки:
```bash
npm run build
uv run ruff check .
uv run ruff format .
uv run mypy .
uv run pytest
```
- Запускай только те проверки, которые соответствуют изменённой части проекта.
- Git Bash неправильно интерпретирует `/PID`. Используй PowerShell.

## Безопасность изменений

- Не используй непредсказуемые PowerShell-команды вроде `-replace` или сложных пайплайнов для изменения кода.
- Для ручных правок используй надёжный patch/edit workflow, чтобы не ломать кодировку и структуру JSX.
- Не делай destructive git-команды без явного разрешения.
- Не трогай чужие незакоммиченные изменения, если они не мешают задаче.
- Не хардкодь реальные секреты, токены и приватные пути.
- Секреты должны идти через `.env` или конфигурацию окружения.

## aiogram 3.x профиль

- Всё асинхронно: `async def` + `await`.
- Используй `Router` для модульности.
- Регистрируй handlers через `@router.message()`, `@router.callback_query()` и т.д.
- Handlers должны быть тонкими: только валидация + вызов service слоя.
- Используй Magic Filters: `F.text`, `F.photo`, `Command()` и др.
- Для состояний используй FSM (`aiogram.fsm`).
- FSM — только для пользовательских сценариев, не для бизнес-логики.
- Middlewares: `BaseMiddleware` или async callable.
- Bot создавай с `DefaultBotProperties(parse_mode=ParseMode.HTML)`.
- `asyncio.run(main())` + `dp.start_polling(bot)`.
- Никогда не используй глобальные `Bot.get_current()`. Передавай `bot: Bot` явно.
